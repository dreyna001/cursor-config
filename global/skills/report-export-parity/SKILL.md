# Report and Export Parity

Identify the canonical saved report, revision, source snapshots, supported surfaces
and current approval/finalization contract before changing a projection. Read the
project's own report contract for domain labels, section order and display exceptions.
Presentation work grants no authority to run searches, models, or consequential actions.

- Preserve supported answers, findings, evidence identity, caveats, scope, counts,
  source bindings and analyst edits. Compression must not silently discard distinct
  information or turn missing, unavailable, null, empty and zero into the same fact.
- Keep observations, interpretation, uncertainty and proposed investigation distinct.
  Preserve event time versus collection/investigation time and source provenance.
- Use stable citations to the same immutable records on each surface. A label is
  not a replacement for a canonical ID. Do not replace saved snapshots with current
  records; expose unavailable states and retain accessible saved detail.
- Preserve exact saved-version approval and finalization guards, dirty/stale edit
  handling, and historical exports. A renderer change does not authorize rewriting
  prior artifacts or replacing a custom analyst conclusion.
- Assess both surfaces for every change to report meaning or presentation. Record
  each as changed, unchanged with reason, or explicitly deferred. Preserve justified
  medium differences such as interactive disclosures versus printed detail.
- Use the same representative saved fixtures across surfaces, including edited and
  legacy reports, long values, conflicting evidence and unavailable sources. Check
  retained meaning and bindings, not only text or screenshot similarity.
- For PDF changes, generate actual PDFs and render/inspect every page for hierarchy,
  table continuation, links, clipping and legibility. Extraction and unit checks
  alone do not establish visual correctness. Use the installed PDF workflow when available.
- Verify affected browser behavior with the project's supported viewport scope and
  accessibility/workflow checks. Do not broaden into mobile or live model testing
  without task scope. Keep exports complete without exposing unauthorized evidence.

Report source/fixture versions, executed checks, intentional differences and
unverified surfaces. Finite fixture checks do not establish general analytical quality.
