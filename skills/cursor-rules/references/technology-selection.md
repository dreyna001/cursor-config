# Technology Selection

- Inspect manifests, lockfiles, configuration, dependencies, and existing code before choosing technology.
- Preserve an existing valid stack and established project conventions.
- Apply personal defaults only for greenfield work or when no established choice exists.
- Do not add technology merely because it is a preferred option.
- Ask before making a consequential or difficult-to-reverse stack decision.
- For preferred stack defaults, use skill `development-stack`; for implementation details, use the relevant domain rules and skills.

When explicitly asked to review or standardize an existing stack, compare evidence-backed alternatives. Existing usage and personal defaults are not proof of fitness; record tradeoffs and a re-evaluation trigger. Preserve authorized scope and workflow invariants while making the choice.
