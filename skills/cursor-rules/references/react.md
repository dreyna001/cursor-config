# React Rule

When writing React code, make the smallest safe change that preserves the existing architecture, styling, naming, and API contracts. Prioritize readable functional components, typed props, accessible UI, explicit loading/error states, and clean separation between UI, state, and API logic. Do not add libraries, broad refactors, clever abstractions, unsafe HTML, fake data, or unnecessary hooks unless explicitly justified.
