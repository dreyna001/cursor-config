# Requirements Confidence

- On non-trivial tasks, get enough clarity on scope, constraints, and success criteria before coding.
- If an unknown could affect correctness, compatibility, security, or safety, stop and ask instead of guessing.
- Define pass/fail acceptance criteria before implementation.
- Add a dependency only when the current task requires it and existing mechanisms are insufficient; explain the need.
- Stop after planning only when the user requested a plan or an unresolved consequential choice requires approval. Otherwise proceed once the scope and pass/fail criteria are clear.
