# Notable incident workflow

Use only in `llm_notable_analysis`. Read current root and nested `AGENTS.md`
instructions. Use installed global `agentic-security-workflows` with its incident
response reference, `llm-evidence-regression` for analysis/grounding changes,
`report-export-parity` for paired report surfaces and `evidence-field-mapping`
for mapping changes. Do not duplicate those global workflows here.

## Case analysis and archives

Read current `docs/case-analysis-contract.md`; the
[packaged contract](references/case-analysis-contract.md) records product detail.
Preserve typed findings, supported current-alert field literals, exactly three
ranked explanations for new initial analysis (no benign/adversary quota), and
legacy archives with zero through three explanations. Initial analysis generates
no SIEM query and executes no search. Recommendations remain proposals.

Preserve bounded native validation/repair, partial-result warnings, raw attempts,
source provenance, semantic-review limits and existing model-pass budgets. Retain
archives, legacy links, saved search outcomes and unknown/partial distinctions.
Azure completed-analysis reuse requires matching current fingerprints; an upgrade
does not rewrite saved cases or bypass replay validation. Local tests and valid
citations establish neither general narrative truth nor live model quality.

the exception or roll the pilot into cloud products without explicit scope.
