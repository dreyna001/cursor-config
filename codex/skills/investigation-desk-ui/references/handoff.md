# Handoff to another agent

For UI/UX work, start at the permanent local baseline:
`$HOME/.agents/ui-baseline/README.md` (Windows:
`%USERPROFILE%\.agents\ui-baseline\README.md`). On the current workstation,
open [Windows](C:/Users/Daniel.Reyna/.agents/ui-baseline/README.md) or
[WSL](/home/dreyna/.agents/ui-baseline/README.md).
If absent, install the versioned `ui-baseline/` bundle from `cursor-config`;
the app's `docs/suite-ui-standard.md` release copy is the fallback. No GitHub
sign-in is required to read the installed reference. This is the single entry
point for shared rules, adaptation, visual examples, exceptions and validation.
Preserve newer approved login/account, sidebar, typography, colors, layouts,
features and intended behavior; older HTML or guidance cannot override them.

Approved shared UI changes are not complete until the versioned baseline,
its visual companion, all three apps (six frontends), this configuration
repository's reference bundle, and the permanent local baseline are synchronized.
Follow the baseline's “Keeping one baseline” procedure, record app-specific
exceptions and validation, and preserve newer approved behavior and styling.
If any part cannot be updated or verified, report the remaining drift explicitly.

Use the attached **Enterprise Workspace unified HTML visual reference** as a
strong visual preference for the authorized work in **[application/repository]**.
It is the single current visual template; older templates are retired.
It originated in `ai-enabled-threathunting`, with ATO comparisons; it is not an ATO
workflow specification. Read the accompanying visual adaptation contract.

Match the palette, typography hierarchy, density, spacing and component treatment
where practical. Organize the UI around this application's real tasks, roles,
data and existing capabilities. Keep its working framework/accessibility primitives
and translate semantic tokens rather than pasting global CSS over its theme.

Use compact source-inspector **B** where suitable: concise context/fields,
precise citations, optional technical detail and an explicit Open source action.
Preserve full files/viewing, editors, comparisons, pickers, bulk actions and upload
states when needed. Do not remove functionality just because the sample lacks it.

Preserve permissions, approvals, drafts, canonical records, citations, bounded
paging and full exports. Avoid copying synthetic data, fake statuses or prototype
controls into product behavior. Explain meaningful deviations by their user
benefit; use judgment for routine adaptations without unnecessary approval loops.
Verify the destination's important desktop workflows and report real limits.
